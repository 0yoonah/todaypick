# 콘텐츠 출처 관리 기준

외부 RSS 출처를 **어디까지 보여 주고, 어떤 기준으로 추가·제거하는지** 정리한 문서입니다.
소스를 추가하거나 정리할 때, 권리자에게 삭제 요청을 받았을 때 이 문서를 먼저 확인합니다.

TodayPick은 비영리 개인 프로젝트이며 원문을 대체하지 않고 원문으로 안내하는 서비스입니다.
아래 기준은 이 성격을 유지하기 위한 것입니다. 수익화를 시작하면 이 기준을 다시 검토합니다.

## 표시 범위

| 항목 | 기준 | 위치 |
| --- | --- | --- |
| 제목 | 최대 200자 | `rssFeedService.ts` `MAX_TITLE_LENGTH` |
| 설명 | RSS 설명의 앞부분 최대 300자, 카드에는 2줄 | `MAX_DESCRIPTION_LENGTH`, `FeedCard` |
| 본문 | 저장하지 않고 보여 주지 않음 | — |
| 썸네일 | 허용 호스트의 이미지만 고르고 원 출처 서버에서 직접 로드 | `FEED_IMAGE_HOSTNAMES`, `FeedCard` `unoptimized` |
| 원문 | 카드를 누르면 원문 페이지로 이동 | `FeedCard` |

- 썸네일은 Vercel 이미지 최적화를 거치지 않습니다. TodayPick 서버에 복제본을 만들지 않기 위해서입니다(#173).
- 스크랩과 읽은 글은 위 범위의 메타데이터를 스냅숏으로 저장합니다(`scraped_feeds.feed`, `feed_reads.feed`). 본문은 포함하지 않습니다.
- 인용 글쓰기는 원문의 제목·URL·출처만 저장하고 본문을 복사하지 않습니다.

표시 범위를 넓히는 변경(본문 일부 노출, 이미지 저장 등)은 이 문서를 먼저 고친 뒤 진행합니다.

## 소스 추가 기준

다음을 **모두** 만족해야 추가합니다.

1. **공식 RSS가 있다.** 페이지를 긁어 피드를 만들지 않습니다.
2. **최근 1년 안에 새 글이 있다.** `npm run check:feeds`의 최근 글 날짜로 확인합니다.
3. **수집을 막지 않는다.** 봇 요청에 403을 돌려주거나 약관에서 RSS 재게시를 금지하면 추가하지 않습니다.
4. **서비스 제한 안에서 수집된다.** 응답 5MB, 요청 8초 제한을 넘으면 실제 서비스에서 수집되지 않습니다. 제한은 보안 장치라 소스에 맞춰 늘리지 않습니다.
5. **기술 글이 중심이다.** 최근 글 대부분이 홍보·채용·편성 안내라면 추가하지 않습니다.
6. **썸네일 호스트를 확인했다.** 필요한 호스트만 `FEED_IMAGE_HOSTNAMES`에 추가합니다.

여러 사람이 글을 올리는 커뮤니티형 블로그는 글마다 저작권자가 다르므로 약관을 확인한 뒤 판단합니다.

## 소스 제거 기준

다음 중 하나에 해당하면 제거합니다.

- 피드가 파싱되지 않는 상태가 다음 점검까지 이어진다.
- 마지막 글이 1년보다 오래됐다.
- 권리자가 요청했다.

제거할 때 지키는 것:

- 남는 소스의 id는 바꾸지 않습니다.
- 제거한 소스의 이미지 호스트는 `FEED_IMAGE_HOSTNAMES`에 남깁니다. 저장된 스크랩·읽은 글 스냅숏이 그 호스트의 썸네일을 참조합니다.

## 삭제 요청 처리

요청은 `/sources` 페이지와 푸터에 안내한 메일(`CONTACT_EMAIL`)로 받습니다.

1. 요청자와 출처, 요청 내용(수집 중단, 표시 내용 수정)을 확인합니다.
2. 수집 중단이면 `src/data/feeds.ts`에서 해당 소스에 `enabled: false`를 지정해 바로 배포합니다. 피드와 `/sources` 목록에서 함께 빠집니다.
3. 배포 후 RSS 캐시(`RSS_REVALIDATE_SECONDS`, 15분)가 지나면 피드에서 사라졌는지 확인합니다.
4. 이미 저장된 스크랩·읽은 글 스냅숏까지 지워 달라는 요청이면 DB 작업이 필요하므로 별도 이슈로 다룹니다.
5. 처리 결과를 요청자에게 회신합니다.

`enabled: false`는 빠른 차단용입니다. 다시 수집할 계획이 없으면 다음 소스 정리 때 항목을 지웁니다.

## 점검

소스를 추가·정리할 때와 릴리스 준비 때 실행합니다.

```bash
npm run check:feeds
```

| 출력 | 의미 | 조치 |
| --- | --- | --- |
| `✗` 실패 | 요청·검증·파싱 실패. 종료 코드 1 | 원인을 확인하고 다음 점검까지 이어지면 제거 |
| `365일 이상 미갱신` | 마지막 글이 1년보다 오래됨 | 제거 |
| `리다이렉트` | 최종 URL이 설정과 다름 | 최종 URL로 갱신 |
| `허용 목록 밖 이미지 호스트` | 썸네일 후보가 허용 호스트가 아니라 대체 썸네일로 표시됨 | 썸네일이 맞으면 호스트 추가, 본문 이미지·추적 픽셀이면 무시 |
| `발행일 없음` | 날짜를 읽을 수 없음 | 정렬에 문제가 생기므로 추가하지 않음 |

외부 네트워크 상태에 따라 결과가 달라지므로 CI에서는 실행하지 않습니다.

| 유지 | IT데일리, IT동아, GeekNews | 비영리·원문 안내 범위에서 유지, 요청이 오면 즉시 제외. 같은 날 정밀 검토로 IT데일리·IT동아는 v1.11.1에서 제외 (아래 기록) |

유지했지만 다음 점검에서 다시 볼 소스: 네이버 플레이스(마지막 글 2025-11), 뱅크샐러드(2026-01).

- 썸네일 호스트 `boostbrothers.github.io`, `hyper-accel.github.io`, `tech.hancom.com`, `techtopic.skplanet.com`을 추가했습니다. 한글과컴퓨터의 `s.w.org`는 WordPress 이모지라 추가하지 않았습니다.
